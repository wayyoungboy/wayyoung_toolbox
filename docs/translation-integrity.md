# 翻译与存量元数据修复

工具箱 0.6.2 / 影片组件 0.0.20 修复标题翻译的错误跳过条件。

## 翻译判定

- 选择翻译引擎与启用“翻译标题 / 翻译剧情”是不同的配置；关闭字段开关时仍允许按原文整理。
- `OriginalTitle` 只是来源元数据。多站点合并后，当前标题与原始标题可能来自不同站点，不能据此判定当前标题已经翻译。
- 开启标题翻译时，当前标题始终经过所选引擎，已有原始标题仍保留。
- 空响应、原样返回的日文正文及供应商错误会阻止整理发布。演员姓名中保留的日文不作为失败依据。
- 标题与简介的内存更新是整体提交的；简介失败不会留下半成功标题。

上述校验不是通用语言识别或翻译质量评估：不保证检测纯汉字日文、英文标题或部分翻译。

## 测试

回归测试覆盖跨站点合并、原始标题误判、空结果、未翻译响应、失败时不修改源视频，以及显式关闭翻译。

```sh
cd modules/media/third_party/javsp
go test -race ./internal/translate ./engine ./cmd/nfo-translate
go test ./...
```

## 存量 NFO

维护命令 `cmd/nfo-translate` 默认只读检查；不会自动作为定时任务运行，也不会移动视频或重建媒体库。

```sh
go run ./cmd/nfo-translate -root /absolute/path/to/completed-library
```

写入需要显式 `-apply`、库外新建的私有 `-backup` 目录，以及从标准输入传入的 DeepL 配置 JSON（`api_key`、`proxy`）。不要把真实密钥写入仓库、日志或命令行参数。默认使用 DeepL 官方 HTTPS 接口，不接受跳转，不跳过证书检查。

工具只选择去除演员姓名后仍含日文假名的标题/简介。保留其他 XML 字节、图片引用、未知字段、文件权限和属主；原 NFO 与前后校验和保存在备份目录。覆盖前重新核对文件身份和内容，避免覆盖并发修改。重复执行时已修复条目不再翻译。

修改 NFO 不代表媒体库一定重新读取。应另外核对飞牛影视中对应条目的标题与简介；必要时通过其原生元数据编辑入口同步，保留原条目、观看记录和收藏。部分版本的编辑页会将评分四舍五入，应在修复前后核对并保护原评分。
