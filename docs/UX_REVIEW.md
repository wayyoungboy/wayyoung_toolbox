# 工具箱体验改进 · 2026-09-23

本轮目标：用户能找到下一步，知道配置是否保存、任务是否真正执行，以及出错后该去哪里处理。优先改善工具箱公共入口和备份完整操作链，不改变业务任务或目录权限。

## 布局与视觉约束

保留飞牛浅色工具界面和系统中文字体，不引入新的组件库。

```text
工具列表 │ 模块名称、版本、服务开关
         │ 当前模块的功能导航
         │ 需要处理的事项 / 任务内容
         └ 配置弹窗：目录 → 定时 → 保存与下一步
```

蓝色 `#1269ed` 表示操作，深灰 `#172033` 用于正文，浅灰 `#f7f8fb` 用于背景；绿色 `#17633f` 表示明确成功，橙色 `#976007` 表示待处理。服务已启动与业务任务成功必须分开表达。

## 已完成

- 修正备份嵌入导航继承 `100vh` 的高度缺陷，主内容不再被推到首屏之外。备份、影片、音乐使用统一的紧凑功能导航；独立应用样式保留。
- 总览区分需要处理、尚未检查和未启用，待处理模块优先显示；详细诊断按需展开，避免默认展示整页日志。
- 保留显式只读检查，不在打开总览时自动扫描、提交任务或扩大授权。
- 备份检查包含现有任务的最近失败、中断和待确认结果；不把挂载写入视为云端完成。
- 未变化的后台状态不重建总览，保留焦点和阅读位置；诊断详情展开状态也会保留。
- 模块标题下展示实际使用流程；模块名称可换行，避免关键名称被截断。
- 备份配置分为目录与定时两个部分，关闭定时后隐藏相关字段，重新打开保留本次输入。
- 弹窗标题、关闭按钮和保存区域在滚动时保持可见；修改后取消或按 Escape 会提示放弃确认，刷新页面也有未保存提醒。
- 创建、修改任务及保存设置有明确反馈。创建成功后提供独立的“预览此任务”动作，不自动运行。
- 保存成功但后续状态刷新失败时，表单关闭并保留成功反馈，避免误导用户重复创建。
- 状态读取异常与用户操作失败分开显示。连接恢复清除读取错误，但不会隐藏未成功的操作。

## 部署边界

本轮为现有 v0.6.3 的静态界面更新，不是新的 GitHub Release 或 FPK 版本。仅更新工具箱公共前端和备份前端，未重启进程、重装应用或改动后端；原静态资源已备份，旧资源保留以兼容已打开页面。

更新前后校验：进程 PID、模块开关、备份状态、硬件配置、音乐配置的文件摘要一致，备份可选授权目录列表一致。实机备份任务及记录仍为零。原来已打开的未保存表单没有刷新或提交。

总览中的业务待处理事项不会因界面更新被自动消除。此次不修复存量媒体、不删除文件、不修改定时计划，也不代替用户创建实际备份任务。

## 后续重点

优先将业务失败记录中的“原因 → 可执行的处理操作 → 重试后的结果”做成闭环；任何批量重试、删除、搬运和重新入库均应保持明确范围与确认，不用绿色服务状态代替实际任务结果。
