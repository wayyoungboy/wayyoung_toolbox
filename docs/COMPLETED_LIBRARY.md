# 已有影片番号去重与投递确认

工具箱 0.6.1 / 影片采集任务中心 0.0.19。

## 使用

1. 在“设置 → 目录与命名”设置可读取的“整理完成目录”。
2. 在“订阅来源”页面下方点击“识别已有番号”，可查看、搜索、分页浏览已识别番号及其示例文件路径。
3. 每次订阅执行都会重新核对这个目录，匹配到已有番号的条目显示“整理完成目录中已存在”，不会加入 qB。恢复尚未投递的队列任务时也会再次检查。

手动识别只遍历文件名和文件属性，不读取视频内容、不刮削、不下载、不移动、不删除文件。列表是内存中的最近快照，重启后可重新识别；去重判断不依赖这份页面快照。目录配置变化或读取失败后，不使用旧列表代替成功检查。

## 识别范围与边界

- 只认配置的视频扩展名、普通文件且大小大于零；递归识别子目录。
- 支持大小写、`_CH.HD`、`-C`、标题文字、FC2/FC2PPV 等已有番号形式的规范化。
- 空目录、零字节文件、NFO、图片、符号链接、`.part` 等临时文件不算已有影片。
- 文件名出现多个不同番号，或者缺少完整番号时，不猜测；页面展示无法识别数量和最多 20 个示例。
- 同番号不同版本/清晰度也会跳过。这是“编号存在”判断，不是视频完整性或内容相同的证明。
- 单次最多遍历 200,000 个目录条目。显式配置的整理完成目录不可读取或超过上限时，暂停新投递，不把失败误判为空库。
- 已经发出的 qB 投递不通过本地去重丢弃；它们仍按原任务身份确认与处理。不会清理已存在的下载或已完成历史任务。

## qB 延迟确认修复

`Ok.` 只表示 qB 接受请求，不代表列表中立即可见。后台每 30 秒最多检查 100 条 `dispatching` / `acknowledged` 且需要确认的订阅任务，只执行登录和按原 hash 查询，不再次调用添加种子的接口。

自动关联还需核对最初投递事件时间（允许 30 秒时钟偏差，最晚到原 30 分钟请求窗口结束）和有效内容路径；不接管明显更晚重新添加的同 hash 任务。无法确认身份则保留待处理提示；不会恢复取消的任务。重复查询不会增加投递次数或堆积事件日志。

确认成功后恢复下载阶段。是否搬运、是否继续 JAVSP，由现有自动入库配置决定；搬运过程仍独立核验完成状态、qB 身份、路径边界与实际文件。历史运行记录保留为历史事实，不改写成成功。

## 管理员接口

- `GET /api/library/completed?query=TEST-001&offset=0&limit=50`：读取快照；`limit` 为 1–200。
- `POST /api/library/completed/scan`，JSON `{}`：只读重新识别已配置的目录；不能通过请求指定任意目录。

接口使用应用已有的飞牛管理员权限和同源写请求校验。没有新增绕过权限的入口。
