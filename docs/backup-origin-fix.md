# 备份模块请求来源校验修复（工具箱 0.6.3）

备份组件 0.0.2 修复工具箱内创建任务时出现的“请求来源校验失败”。

## 原因与修复

飞牛 HTTP 局域网入口可能没有 `Sec-Fetch-Site`，同时网关会重写请求的 `Host`。
旧校验回退到 `Referer` 时，只认独立应用 `/app/backup_center/`，未使用已配置的工具箱模块路径。

现在校验使用服务启动时配置的模块前缀。独立部署仍使用原前缀，工具箱部署使用自身模块路径。
不新增域名白名单、不信任调用方的转发头、不关闭来源校验；管理员身份、可信网关、JSON、CSRF token、同源的协议/主机/端口及路径边界检查继续生效。

## 验证

- 先复现合法工具箱请求返回 403，再验证修复后可保存每天定时执行的任务。
- 通过真实工具箱路由和内嵌备份模块验证写入接口。
- 回归旧部署入口、错误模块路径、前缀相似路径、路径穿越、跨站请求、缺失管理员/网关/CSRF 等情况。
- 保存任务不立即执行备份；测试创建与调度计算使用隔离临时目录，不操作真实网盘。

## 更新后

请保存其他模块的编辑内容，再从飞牛桌面重新打开工具箱。服务重启会更换 CSRF token，旧页面需要重新加载。
来源校验修复本身不要求重新授权目录，不自动创建任务、扫描媒体或执行整库备份。

注意：`appcenter-cli install-local` 在已安装应用上可能执行卸载后重装，清除飞牛系统侧的目录授权。
应用数据目录备份并不包含这些系统权限。安装前记录原有授权范围，安装后同时核验共享目录 API 和原生目录选择器；
若授权丢失，通过飞牛原生界面恢复原有目录，不扩大授权范围。仅检查应用数据库和配置保留不足以证明升级完整。
