# 影片采集流程

## 三个目录

在“设置 → 目录与命名”分别设置下载来源、未处理、整理完成目录。整理完成目录填写媒体库实际使用的绝对路径；开启“整理时移动视频”。所有目录都需已存在且应用可访问。

| 位置 | 内容 | 后续动作 |
| --- | --- | --- |
| 下载来源 | qBittorrent 正在下载和已完成的文件 | 完成并确认停止写入后搬运 |
| 未处理 | 待刮削、失败或需要核对的影片 | 识别影片、取得资料、命名和整理 |
| 整理完成 | 归档视频、同名 NFO、封面和剧照 | 由媒体库扫描展示 |

媒体库只需添加“整理完成”目录，不要把下载和未处理目录一并加入。输出文件夹模板相对于整理完成目录，例如 `{actress}/[{num}] {title}`，不要重复添加完成目录名称。

旧配置允许完成目录留空，此时模板相对于扫描目录。流程诊断会显示计算出的绝对位置并提醒风险。原地整理只在来源旁生成资料，不会把视频搬入成品目录。

## 自动与手动入口

1. **RSS 发现**：按订阅筛选条件读取条目。预览模式不下载；正式模式先核对成品目录与持久队列，重复条目会跳过或关联已有任务。配置了独立媒体库却无法读取时，暂停新投递。已在队列中但尚未投递的任务也会在发送前重新核对媒体库。
2. **qB 下载**：记录种子标识和加入时间，等待 100% 完成。状态读取失败不会当成下载完成，也不会盲目重新投递。
3. **下载完成搬运**：手动“立即搬运”或定时检查只处理下载来源范围内的完整任务。停止并确认 qB 不再写入后搬到未处理目录；同名目标只有经过完整内容核验后才能清理重复来源。搬运凭据和队列用于中断恢复。
4. **刮削整理**：开启“入库后整理”会为本次搬运的视频建立影片任务。定时扫描是另一个开关，用来发现人工放入未处理目录的影片；关闭定时扫描不影响已排队影片执行。也可以手动扫描未处理目录。扫描会排除成品目录，并遵守最小大小、扩展名及忽略规则。
5. **整理入库**：取得必要资料，生成 NFO 和图片，按规则移动视频并生成视频同名 NFO。影片队列显示成功才代表整个整理步骤完成。qB 搬运任务成功仅表示搬运和下载记录清理完成。

程序单进程运行，文件整理、搬运和维护操作互斥，避免同时移动或删除同一批文件。流程总览同时显示各阶段排队、运行及未解决错误；完整性检查不属于媒体采集阶段。

## 冲突与失败

| 现象 | 含义与处理 |
| --- | --- |
| 同名 NFO 或视频已存在 | 已有目标可能是另一版本；停止当前步骤并保留文件。不能只按番号或大小判断可删除。 |
| 缺少标题、封面，或站点请求失败 | 资料不齐，任务保留在未处理目录。修正资料源或网络配置后重试。 |
| 未识别出番号或 CID | 文件命名不符合当前刮削器规则；没有日系番号的影片也会出现此情况。核对影片类型和命名后再处理。 |
| 影片未进入队列 | 检查是否低于最小文件大小、扩展名被排除、目录被忽略，或只开启了下载后整理而未手动/定时扫描。 |
| 完成目录变更后旧任务暂停 | 旧任务已有输出计划，程序不会擅自重写凭据或继续写入旧媒体库。核对已生成文件和搬迁情况后恢复。 |

需要处理的状态包括失败、部分成功、超时和待人工处理。取消任务不会删除视频或回滚已经完成的移动；不要用取消来掩盖仍需核对的数据。

下载搬运撞名时使用完整内容比较；媒体维护中的三段采样指纹只用于辅助筛选副本，不能证明整个文件逐字节相同。同番号可能是不同字幕、清晰度或剪辑版本，永久删除前需要核对保留版本。完整性检查用于检测文件是否能解析，媒体编号去重用于避免重复下载，这些检查不能互相代替。素材处理过程中可能短暂生成元数据，媒体队列成功才是成品完成的判据。

修改目录配置不会自动搬迁历史文件。迁移时应先确认没有媒体任务写入，保存清单、禁止覆盖，并核对移动后的文件身份与大小；旧运行日志保留当时的路径以供追溯。
