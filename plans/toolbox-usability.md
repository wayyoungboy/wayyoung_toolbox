# 工具箱可用性审查与收敛

## 目标与边界

保留五个模块与当前配置，改善统一入口、导航连续性、配置/权限可见性及危险操作反馈。沿用现有飞牛视觉与单进程架构，不重写各模块业务引擎。不触发正式下载、备份、转换、扫描、清理或风扇策略变更，不推送仓库。

已知问题：根页面切换模块会销毁 iframe 和未保存表单；模块启用被误认为业务已就绪；缺少工具箱总版本；模块关闭缺乏确认；两层侧栏占用空间；目录授权失败反馈不明确。

## 步骤（顺序依赖）

1. **建立基线与只读审查**：跑现有测试，读取 NAS 的实际运行状态、配置字段是否齐全、授权目录和挂载状态。记录问题，不输出密码/令牌/完整私有配置。独立审查本方案。
   - 验收：明确五模块使用路径和权限边界；区分配置存在、连接成功、业务执行成功。
2. **测试驱动的交互修复**：先写回归测试，后实现统一总览/检查入口、整包版本、切换模块保留会话、合理的紧凑导航与关闭确认；目录选择只提供已有授权/原生授权，不放宽目录白名单。状态检查只调用安全的读取 API，失败显式展示、请求有超时。补桌面与窄屏浏览器回归。
   - 验收：未保存表单切换回来仍在；禁用请求必须确认；总览不会执行任务；状态失败不会误报正常；隐藏 iframe 无原生授权桥能力；原生目录选择回归仍通过。
3. **安装与实机验证**：检查活跃任务，停应用后一致性备份整个 appdata 和旧程序；构建 FPK，按当前 fnOS 可用路径安装；验证版本、数据库/配置/记录保留及五模块 API/界面；只做只读连接/目录权限测试。
   - 验收：五模块恢复原启用状态，配置与升级前一致（若授权必要变更单独说明）；真实界面可打开、选择目录可响应；失败项明确交代。用户没有指定的新任务/时间表不擅自创建。
   - 回滚：停止新版，恢复已备份旧程序/清单与一致性 appdata，恢复原运行状态；不动媒体或云端数据。

## 高风险点

- 现有未提交媒体工作流修改属于既有工作，保留且一起测试，不覆盖。
- 缓存 iframe 需要限制原生权限桥只能由当前可见备份模块调用；模块停止或重启时必须失效。
- 保留状态不是自动保存，浏览器刷新/应用停止仍需明确提示。
- root 运行并不代表 fnOS 目录授权成功，不以 chmod 777 或扩大根目录权限掩盖配置问题。
- 只读检查失败不应通过自动重试任务或打开定时执行“修复”。
- 部署前确认进程实际退出，不仅依赖 stop 返回；保存原始授权清单与完整 SQLite WAL/SHM。恢复应用会恢复既有计划/硬件策略，这不是额外测试任务；不打开原本关闭的自动化。
- 页面缓存以模块启动代次失效；原生权限桥在调用前和完成后校验当前页面，离开后又返回也丢弃迟到结果。停止操作全局防重入。

## 本轮结果

- 已完成统一总览、稳定模块会话、紧凑二级导航、原生/已有授权目录选择、关闭确认、配置加载/保存失败保护和安全退出。保留现有单进程业务引擎。
- 0.6.0 已构建并安装实机，五模块恢复原运行状态。升级前进程已退出，完整数据与旧程序已备份；JAVSP/硬件/模块开关/备份配置、目录授权均一致；所有旧数据库记录仍在，下载队列有正常轮询更新。
- Go 全模块 vet/race、115 项前端测试、7 项浏览器回归通过；工具箱与备份前端覆盖率语句 92.41%、分支 84.88%。实机验证了五模块打开、只读配置检查、目录弹窗、定时开关、表单跨模块保留和取消关闭。
- 未新建或执行实际备份、扫描、转换、清理任务，也未改变硬件策略。现有自动计划按原配置恢复。
- 待用户确认音乐输入/输出目录与新的备份目录/授权方案；未把空配置伪装成已就绪。原有影片队列待处理事项仍明确显示，未用自动删除或重投递消除错误。
